# UI/UX Audit — Blog Post Detail (`/blog/[id]`)

## Summary
This is an ambitious template — sticky scroll-spy TOC, share/copy-link, related posts, Article + Breadcrumb JSON-LD — and most of the plumbing works. But two things undercut it in practice: the entire right-hand sidebar (TOC, WhatsApp share, copy-link, quote CTA) is `hidden` below `lg`, so roughly half of real-world mobile/tablet readers lose share functionality and navigation entirely, not just a "nice to have"; and the TOC's heading-depth filter (`h1`/`h2` only) produces a near-useless single-entry table of contents on posts that structure their content as one `h2` with several `h3` subsections (e.g. the OHS Act post). There's also a color-system regression worth calling out: prose links and the TOC's active-state highlight use `--primary` (decorative/structural) where the new design system explicitly says active nav states and links should use `--interactive`.

## Findings

| Severity | Area | Finding | Recommendation | Location |
|---|---|---|---|---|
| High | Mobile UX / Functionality | The entire sidebar — TOC nav, WhatsApp share, Copy link button, and the "Need a quote?" CTA — lives inside `<aside class='hidden lg:block ...'>`. Below `lg` (1024px) none of it renders at all, not even collapsed. That means every phone and most tablet visitors reading a post have **no share button, no copy-link, and no in-page navigation** — this isn't a layout squeeze, it's a lost feature. | Don't hard-hide the whole aside on mobile. At minimum, render the Share buttons and the quote CTA inline in the article flow below `lg`; consider a collapsible `<details>`-based TOC above the article for small screens. | `src/pages/blog/[id].astro:174-248` |
| High | TOC content match | `tocHeadings` only keeps `depth === 1 \|\| depth === 2` (i.e. `h1`/`h2`). Actual post content (see `src/content/blog/*.md`) is authored with `##` as the top-level section and `###` for subsections — e.g. `ohs-act-construction-compliance.md` has exactly **one** `##` heading ("Key OHS Requirements for Construction Sites") wrapping five `###` items (Health & Safety Plan, Safety Officer, Risk Assessments, PPE, Toolbox Talks). The rendered TOC for that post is a single link, which adds a whole sidebar card for essentially no navigational value while the more useful subsection anchors are invisible. | Include `depth === 3` in `tocHeadings` (or make the cutoff configurable), and consider indenting `h3` entries under their parent `h2` in the TOC markup. | `src/pages/blog/[id].astro:16`; content shape confirmed in `src/content/blog/ohs-act-construction-compliance.md:13-40` |
| High | Color system | Prose link color and the TOC active-heading highlight both use `--color-primary`, the structural/decorative token — but the design system explicitly assigns "buttons, links, active nav states, form focus rings" to `--interactive`. This is a direct, testable mismatch between the stated system and the implementation. | Change `--tw-prose-links` (and `--tw-prose-invert-links`) to `var(--color-interactive)`; change the TOC observer's active-state classes from `text-primary` to `text-interactive`. | `src/styles/starwind.css:208,226` (prose links); `src/pages/blog/[id].astro:333,340` (TOC active state script) |
| Medium | Reading measure | The article column has `prose-lg max-w-none` — `max-w-none` strips Tailwind Typography's built-in `65ch` measure. On a `lg` viewport the article column is roughly `1fr` of a `[1fr_240px]` grid inside a 1280px container (~950-980px wide), and at `prose-lg`'s ~18px body size that's well over 100 characters per line — far past the ~50-75ch that's readable for body copy. | Drop `max-w-none` (let Typography's default `65ch` apply) or replace it with an explicit `max-w-[70ch]`/`max-w-3xl` on the prose wrapper. | `src/pages/blog/[id].astro:166` |
| Medium | Related posts grid | The "More from the Blog" grid uses `grid-cols-1 md:grid-cols-3` — jumping straight from 1 to 3 columns at 768px — while the same card component on the listing page (`src/pages/blog/index.astro:49`) steps through `md:grid-cols-2 lg:grid-cols-3`. At tablet widths (768-1023px) related-post cards are visibly narrower/more cramped than the identical card used elsewhere on the site. | Match the listing page's breakpoints: `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`. | `src/pages/blog/[id].astro:257` |
| Medium | Copy-link failure state | `copyBtn`'s click handler swallows clipboard errors with an empty `catch { /* silent fallback */ }` — if `navigator.clipboard.writeText` fails or is unavailable (non-secure context, older browser, denied permission), the button silently does nothing: label stays "Copy link", no error is surfaced to sighted or screen-reader users. The `aria-live="polite"` region added in the prior fix only ever announces success. | On catch, update `copyLabel` to something like "Couldn't copy — try selecting the URL" (or fall back to a `prompt()`/manual-select flow) so the `aria-live` region has something to announce either way. | `src/pages/blog/[id].astro:356-362` |
| Low | Scroll-spy robustness | The `IntersectionObserver` callback resets *all* TOC links then highlights whichever entry is last in `entries` when multiple headings are simultaneously intersecting the `-20% 0px -70% 0px` band (e.g. short sections between two headings). Iteration order isn't guaranteed to match document order, so on some posts the highlighted TOC item could visibly flicker between two entries while scrolling. | Track the intersecting heading closest to the top of the margin band explicitly (e.g. pick the smallest `boundingClientRect.top >= 0`) rather than "whichever fires last in this batch." | `src/pages/blog/[id].astro:328-349` |
| Low | Reading time accuracy | `wordCount` is computed via `post.body?.split(/\s+/).length` — `post.body` is the raw Markdown source, so heading markers, link syntax (`[text](url)`), code fences, and front-matter-adjacent characters all inflate the word count somewhat versus the rendered text a reader actually sees. | Not urgent given short posts, but if precision matters, strip Markdown syntax (or use the rendered `Content` text) before counting. | `src/pages/blog/[id].astro:38-39` |
| Low | "Back to top" affordance | The sidebar's "Back to top" link uses `href='#'`, which does scroll to top (works), but it's not a semantically anchored target (no `id="top"`) and there's no `focus-visible` styling defined anywhere on this page for keyboard users tabbing through the sidebar's links/buttons. | Low priority functionally since `href="#"` does work; add a shared `focus-visible` ring treatment across the sidebar's interactive elements (TOC links, back-to-top, share/copy buttons) for keyboard-user clarity. | `src/pages/blog/[id].astro:200-206` |

## What's Working Well
- Article + Breadcrumb JSON-LD (`BlogPosting`/`BreadcrumbList`) is implemented — the schema gap flagged in the prior audit is resolved. `src/pages/blog/[id].astro:42-69,78-79`
- The `aria-live="polite"` announcement on the copy-link label, flagged as missing in the prior audit, is now present and correctly wired to the success path. `src/pages/blog/[id].astro:230`
- Decorative icon usage (author-avatar circle, calendar/clock meta icons, TOC/share icon strokes) consistently uses `--primary`, matching the design system's stated role for it. `src/pages/blog/[id].astro:139-140,146,151`
- Cover-image fallback pattern is applied consistently with the listing page (`post.data.coverImage ?? '/images/placeholder.svg'`), including on related-post cards.
- Heading hierarchy is coherent: single page `<h1>` in the hero (outside `.prose`), with post content starting at `##`/`###` — no duplicate/competing `h1`s inside the article body across the sample content checked.
- `.prose` typography overrides (`h2`/`h3` spacing, table/blockquote/code styling in `src/styles/starwind.css:242-289`) correctly reference design tokens (`--color-border`, `--color-accent`, `--color-primary`) rather than hardcoded values, so dark mode and future palette tweaks propagate automatically.
- The bottom "Back to Blog" / "Request a Quote" bar gives every reader a clear next step regardless of how far they scrolled, independent of the sidebar CTA.
