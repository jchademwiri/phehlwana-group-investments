# UI/UX Audit — Terms of Service (`/terms-of-service`)

## Summary
This is a fresh page, and it was clearly built by deliberately adapting the Privacy Policy template rather than blindly copy-pasting it — the header pattern, prose wrapper, and contact-box styling match, but the content and the contact box's field list are genuinely different where they need to be (no "Information Officer" line, since ToS has no such role). The page correctly links to Privacy Policy at the bottom, closing half of the cross-link gap noted in that page's own audit. The remaining issues are the same systemic ones affecting its sibling: wide prose measure and the `.prose` link-color token.

## What's Working Well
- Structurally matches Privacy Policy almost exactly (same header section classes, same `prose dark:prose-invert max-w-4xl mx-auto` wrapper, same `hr` divider, same closing contact-box markup) — the pair reads as one coherent legal-pages system, not two unrelated designs. This was explicitly checked and confirmed: `src/pages/terms-of-service.astro:11-32` line up 1:1 with `src/pages/privacy-policy.astro:11-32` in structure.
- Despite the shared template, the content itself is properly adapted rather than duplicated: 10 ToS-specific sections (acceptable use, IP, liability limitation, third-party links, governing law, changes-to-terms) with no leftover POPIA/privacy language bleeding in.
- Contact box (`terms-of-service.astro:89-94`) correctly drops the "Attention: The Information Officer" line that Privacy Policy's box has (`privacy-policy.astro:99`) — a role that only makes sense in a POPIA/privacy context — showing the box wasn't copy-pasted verbatim.
- Reciprocal cross-link to Privacy Policy is present and uses the correct `text-interactive` treatment for a clickable in-body link (`terms-of-service.astro:97`).
- "Last updated: July 27, 2026" date is plausible for a page added "last week" relative to the given current date (2026-08-02), and the "Changes to These Terms" clause (Section 9) correctly explains how that date will be kept current.
- Responsive behavior is identical to, and inherits the same soundness as, Privacy Policy — no fixed-width or overflow-prone elements found.
