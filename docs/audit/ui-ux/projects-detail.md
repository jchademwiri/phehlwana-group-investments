# UI/UX Audit — Project Detail (`/projects/[id]`)

## Summary
The two previously-flagged issues from the older audit are genuinely fixed: the fake-lightbox affordance (`cursor-zoom-in`/`role='button'`/`tabindex='0'` on the main image) is gone, and the thumbnail strip now uses correct `<ul><li><button>` semantics instead of an invalid `role='listitem'` on a raw button. The interactive-blue retarget on the gallery thumbnails also landed correctly and is visually coherent with the design system. The main issues now are a genuine content bug (the `Security` category falls through to a generic muted badge instead of getting its own color, unlike the overview page), a timing mismatch in the fade transition that can cause a visible "pop," and a missing `aria-current`/`aria-pressed` on the active thumbnail so screen-reader users can't tell which image is showing.

## What's Working Well
- **Interactive-blue retarget verified correct on the gallery**: both the initial Astro-rendered active border (`i === 0 ? 'border-interactive' : 'border-transparent hover:border-interactive/50'`, lines 244-246) and the JS click handler's active-state swap (`thumb.classList.add('border-interactive')` / `.remove('border-transparent')`, lines 522-527) use the same token consistently — no mismatch between SSR and post-interaction state, and the hover treatment (`border-interactive/50`) reads as a sensible "not yet active but hinting" state rather than looking broken.
- Thumbnail focus styling correctly uses the interactive token too — `focus-visible:outline-2 focus-visible:outline-interactive` (line 243) — so keyboard users get a visible, on-brand focus ring; since thumbnails are plain `<button>` elements, Tab + Enter/Space works with no custom key handling required.
- Both older-audit issues are confirmed fixed: no fake-interactive `role`/`tabindex`/zoom-cursor on the static hero image (lines 214-218), and the thumbnail strip now uses valid `<ul>`/`<li>`/`<button>` nesting (lines 234-263) instead of the invalid `role='listitem'` on a bare button.
- Breadcrumb is fully semantic: `<nav aria-label='Breadcrumb'>` with an ordered list, `aria-hidden` separators, and `aria-current='page'` on the current item, plus `truncate max-w-xs` so a long project title doesn't blow out the layout (lines 85-123). It's paired with a matching `BreadcrumbList` JSON-LD block (lines 60-68, 77) for SEO.
- Two-column layout (`lg:grid lg:grid-cols-[1fr_280px] lg:gap-12`, line 279) collapses cleanly to a single stacked column below `lg` with no explicit mobile overrides needed — the sidebar naturally flows after the article body in source order, which is a reasonable reading order on mobile (content first, then metadata/CTA).
- Sidebar uses `sticky top-32 self-start` (line 288) so the info card and CTA stay in view while scrolling a long case study on desktop, without needing JS.
- Info-sidebar icons consistently use `text-primary` (structural/decorative navy) rather than `interactive` — correct per the new color split, since these are non-interactive labels (Client, Project No., Category, Location, Duration), not controls.
- CTA placement is sensible and non-repetitive for a long-form page: one contextual CTA card in the sticky sidebar (pre-fills `?service=<category>` on the contact link, line 435) and one at the very bottom of the page for users who scroll past the sidebar on mobile — both correctly styled with `bg-interactive`/`hover:bg-interactive/90` since they're real click targets.
