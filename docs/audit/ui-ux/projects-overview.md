# UI/UX Audit — Projects Overview (`/projects`)

## Summary
The category filter is genuinely well built: native `<button>` elements, correct `role="group"`/`aria-pressed`/`aria-live` empty state, and the recent `border-interactive`/`bg-interactive` retarget landed cleanly — the server-rendered "All" button and the JS click handler toggle the exact same class set, so there's no flash-of-wrong-color or state drift between initial paint and interaction. The grid, image handling, and empty state are all solid. The main gaps are a hardcoded, hand-maintained category-color map that duplicates logic across two files (and is already inconsistent with the detail page — see the paired audit), plus a couple of small polish items around focus affordance and filter state not surviving navigation/reload.

## What's Working Well
- **Interactive-blue retarget verified correct**: the "All" pill's server-rendered classes (`bg-interactive text-primary-foreground border-interactive`, line 64) exactly match what the JS click handler applies on activation (lines 192-194), and the inactive/hover state consistently uses `hover:border-interactive` (line 65) rather than the structural `primary`. No visual pop or logic mismatch between SSR and hydration state.
- Filter buttons are real `<button type="button">` elements inside a `role="group"` with `aria-label`, each carrying `aria-pressed` kept in sync by JS (lines 58-70, 190-191) — fully keyboard operable (Tab + Enter/Space) with no custom key handling needed.
- Empty state (`#no-results`, lines 152-158) exists, reads clearly ("No projects found in this category."), is `aria-live="polite"` so screen-reader users are notified of the filtered result count changing, and its visibility toggle logic (`visible > 0`) is correct.
- Image handling is careful: `Picture` component with explicit `width`/`height`, `loading='lazy'`, `decoding='async'`, wrapped in a fixed `aspect-16/10` container — prevents layout shift regardless of source image dimensions, and cover images fall back to a placeholder (line 94).
- Whole-card-is-a-link pattern is implemented correctly and accessibly: a single absolutely-positioned `<a>` with a descriptive `aria-label` (lines 85-89) rather than nested/duplicate interactive elements, avoiding double Tab stops.
- Responsive grid (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`, line 76) and filter pill wrapping (`flex flex-wrap`, line 52) both degrade sensibly on narrow viewports.
- Category badge dot/pill colors correctly bypass the new `interactive` token — since they're purely informational, not something users click, keeping them off the interactive palette is the right call per the new color system's intent.
