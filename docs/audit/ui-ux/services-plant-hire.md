# UI/UX Audit — Plant Hire (`/services/plant-hire`)

## Summary
The strongest page in the set from a UX-pattern standpoint — it's the only detail page to break from the repetitive card grid, using a comparison layout (Wet/Dry hire), a genuinely scannable equipment table, and a numbered how-to-hire list. The table's status badges have a real dark-mode contrast problem worth fixing, and the equipment table has minor scannability/responsive issues. Also affected by shared layout issues — see `services-layout-shared.md`.

## Findings
| Severity | Area | Finding | Recommendation | Location |
|---|---|---|---|---|
| High | Color contrast (dark mode) | The "Available" status badge uses `bg-success/20 text-success-foreground`. `--success` is `color-green-300` (light green) and `--success-foreground` is `color-green-950` (near-black green) in **both** light and dark mode (`starwind.css:110-111, 152-153` — this token pair was not adapted for dark mode). At `/20` opacity over the dark-mode `--card` background (`#121212`), the badge background renders as a very dark, barely-tinted surface, while the text sits at near-black green (`green-950`) — producing very low contrast, likely failing WCAG AA. This affects 5 of 8 rows in the equipment table (every row where `operator: true`). | Add a dark-mode-specific `--success`/`--success-foreground` pair (e.g. a brighter green text on dark, similar to how `--primary` and `--interactive` were already given dark-mode variants), or use a higher, non-opacity-dependent background for badges (e.g. solid `bg-success` at full opacity with dark text, or `text-success` on a neutral badge background) so contrast doesn't depend on blending opacity against an unpredictable page background. | `src/pages/services/plant-hire.astro:133-135`; tokens at `src/styles/starwind.css:110-111, 152-153` |
| Medium | Table responsiveness | The equipment table is wrapped in `overflow-x-auto` (good), but on narrow mobile viewports the 3-column table (Equipment / Description / Operator) with `whitespace-nowrap` on the Equipment column (`plant-hire.astro:127`) forces horizontal scrolling for the full table rather than allowing description text to wrap naturally within a narrower first column — the whole table becomes scroll-locked rather than gracefully reflowing. | Consider a card-based layout for equipment on mobile (`sm:hidden` cards + `hidden sm:table` for the table), matching the card pattern used on every other detail page, since 8 rows of horizontally-scrolling table on a phone is a worse experience than the card grids elsewhere on the site. | `src/pages/services/plant-hire.astro:108-151` |
| Low | Ambiguous data value | `Tools & Equipment` has `operator: null` rendering "N/A" in the Operator column (`plant-hire.astro:44, 142-144`) — but "N/A" for an operator column on hand tools is a reasonable but unexplained value; a first-time reader may wonder if it means "not applicable" or "not available," which have very different implications for a hire decision. | Consider a short tooltip or footnote clarifying "N/A" means "not applicable — no operator required for hand tools," to remove ambiguity. | `src/pages/services/plant-hire.astro:44, 142-144` |
| Low | CTA/action gap | The page has a numbered "How to Hire" 4-step process ending in delivery/collection, but no equipment-specific CTA (e.g. "Check availability for [item]") — the only CTA is the generic bottom-of-page `ContactCTA` from the shared layout, so there's a long scroll from any given equipment row to the nearest action. | Consider a per-row or per-table "Request a quote for this equipment" micro-CTA, or at least an inline CTA directly after the equipment table rather than only at the very bottom of the page. | `src/pages/services/plant-hire.astro:101-152` |

## What's Working Well
- Best differentiation from the repetitive card-grid pattern used elsewhere — the Wet/Dry hire comparison, equipment table, and numbered hire-process list each use the layout best suited to their content type rather than forcing everything into identical cards.
- Equipment table is genuinely scannable: consistent column structure, clear status badges (contrast issue aside), and sensible row order (heavy equipment first, tools last).
- "Best for:" micro-copy under each hire-type card is a smart, concise decision aid that doesn't exist on any other detail page.
- Correct `text-primary` usage for the numbered step badges (decorative, not clickable).
