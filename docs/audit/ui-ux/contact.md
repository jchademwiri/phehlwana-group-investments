# UI/UX Audit — Contact Us (`/contact`)

## Summary
This is the strongest of the three pages functionally: a real, server-validated form with field-level errors, sensible field grouping, correct use of `--interactive` for focus rings and buttons, a honeypot, and a well-structured sidebar with clear contact channels. The biggest issues are structural/consistency rather than raw usability: the page hand-rolls its own header instead of the shared `PageHeader` component (losing breadcrumbs in the process), form errors aren't exposed to assistive tech via `aria-invalid`, and the mobile content order buries quick-contact info (phone/address/WhatsApp) below a long form.

## Findings

As a direct result, Contact has **no breadcrumb nav** ("Home / Contact") while About does — an inconsistent navigational aid across the site, and a maintenance risk (any future header-style change has to be applied in two places). | Replace the manual header block with `<PageHeader label="Contact Us" title="Have a Project in Mind?" subtitle="..." breadcrumbs={[...]} />`. | `src/pages/contact.astro:78-95` vs `src/components/sections/PageHeader.astro` |

## What's Working Well
- Correct, thorough use of `--interactive` for every genuinely interactive element on the page: input focus rings, submit button, submit button's `focus-visible` outline, and link hovers (`hover:text-interactive`) in the sidebar — a clean split from the decorative `text-primary`/`bg-primary/10` used on icon dots and eyebrow labels.
- Field grouping (Name+Email, Phone+Service on a `sm:grid-cols-2`, then full-width Subject/Message) mirrors natural form-filling order and mobile-collapses cleanly to one column per row.
- Every required field has a properly associated `<label for>`, a visible red-asterisk indicator, `required` on the input, and server-side error messages that persist submitted values (`prev.name`, etc.) so users don't lose their input on validation failure.
- Non-field-level errors get a distinct `role="alert"` banner (`contact.astro:108-132`) separate from per-field errors — good separation of global vs. local error feedback.
- Honeypot field is properly hidden (`absolute left-[-9999px]`, `tabindex="-1"`, `aria-hidden`) without relying on `display:none`, which is the more bot-resistant approach.
- Map iframe has a descriptive `title`, `loading="lazy"`, and `referrerpolicy` set — solid baseline for both a11y and performance.
- FAQ accordion has correct `aria-expanded`/`aria-controls` wiring and matching `id`s on the `<dd>` panels.
