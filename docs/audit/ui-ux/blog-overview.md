# UI/UX Audit — Blog Listing (`/blog`)

## Summary
The listing page is structurally solid: a responsive card grid, a safe cover-image fallback, a sensible empty state, and correct use of `--interactive` on the one truly interactive element per card (the title-hover color). The design-token usage is mostly consistent with the new primary/interactive split. The two real problems are a keyboard-accessibility gap on the "whole card is a link" pattern (focus ring gets clipped by `overflow-hidden`), and cover art that is still generic SVG line-art rather than photography for a construction/plant-hire/security brand — both worth fixing before this page is called done.

## Findings

| Severity | Area | Finding | Recommendation | Location |
|---|---|---|---|---|
| High | Accessibility / Keyboard | Each card is a single full-bleed link (`absolute inset-0 z-10`) inside an `article` with `overflow-hidden`. No `focus-visible` style is defined anywhere on the page, so keyboard users get only the browser's default outline — which sits flush with the card edge and is clipped by the parent's `overflow-hidden` (compounded by `rounded-xl`). Tabbing through the grid gives little to no visible focus indicator. | Add an explicit `focus-visible` treatment on the card anchor (e.g. `focus-visible:outline-2 focus-visible:outline-interactive focus-visible:outline-offset-2` applied to the `article` via `:has()`/`group-focus-within`, or move the ring to the `article` wrapper) so it isn't dependent on the clipped default outline. | `src/pages/blog/index.astro:51-58` |
| Medium | Visual / Brand | All four cover images are generic vector line-art illustrations (`ohs-safety.svg`, `building-maintenance.svg`, `plant-hire-guide.svg`, `waste-management.svg`), not real photography. For a construction/plant-hire/security company this reads as generic/stock rather than corporate. Carried forward from the prior audit — still true. | Replace with real jobsite/plant/security photography per post topic; keep the `Picture` fallback wired to `/images/placeholder.svg` for future posts without art yet. | `src/content/blog/*.md` (`coverImage` fields); `public/images/blog/` |
| Medium | Color system consistency | The "Read more" affordance (text + chevron) uses `text-primary`, the structural/decorative color, even though it functions as a click cue paired with the card's link. Meanwhile the card title correctly switches to `text-interactive` on hover. The two visual cues for "this card is clickable" use two different colors. | Either make "Read more" pick up `group-hover:text-interactive` to match the title, or intentionally leave it neutral (`text-muted-foreground`) so `primary` isn't doing double duty as both a decorative and a click-affordance color. | `src/pages/blog/index.astro:103-106` |
| Low | Empty state | The zero-posts message (`"No posts published yet - check back soon."`) is a dead end — centered text with no link back into the site (e.g. to `/contact` or `/`). Low traffic path, but currently a blank room. | Add a small link/button back to the homepage or contact page under the message. | `src/pages/blog/index.astro:44-47` |
| Low | Tags | Tags render as static, non-interactive pills (`bg-accent text-accent-foreground`) — correctly non-clickable since they sit under the full-card overlay link (`z-10`), but there is no tag-based filtering/browsing anywhere on the site, so tags are decorative-only. Not a bug, just worth flagging as an unrealized affordance if editorial expects tag browsing later. | If tag filtering isn't planned, consider whether showing tags on every card is worth the visual noise vs. just date + excerpt. If it is planned, tags will need to move outside the overlay link's z-index or become their own links. | `src/pages/blog/index.astro:96-102` |
| Low | Responsive grid | Grid breakpoints are `grid-cols-1 md:grid-cols-2 lg:grid-cols-3` (`md`=768px, `lg`=1024px), which is reasonable, but note the "More from the Blog" related-posts grid on the detail template jumps straight to 3 columns at `md` (768px) instead of 2 — the same card component looks correspondingly tighter there at tablet widths. See `docs/audit/ui-ux/blog-detail.md` for detail. | Align breakpoints between the two grids (both use the card component) so tablet-width behavior is consistent site-wide. | `src/pages/blog/index.astro:49` (cf. `src/pages/blog/[id].astro:257`) |

## What's Working Well
- Cover-image fallback pattern is correct and simple: `post.data.coverImage ?? '/images/placeholder.svg'` guarantees every card always has art, and `alt=''` is appropriate given the wrapping anchor already carries a descriptive `aria-label` (`src/pages/blog/index.astro:57, 63`).
- Card title hover correctly uses `--interactive` (`group-hover:text-interactive`, line 85) rather than `--primary` — this is exactly the split the new design system asks for.
- Empty state is handled at all (`posts.length === 0` branch) rather than silently rendering an empty grid — many teams skip this.
- Excerpt uses `line-clamp-3` to keep card heights visually consistent regardless of description length, and the date/tag/"read more" footer row is pinned to the bottom of the flex column (`mt-auto`) so short and long excerpts don't misalign card footers.
- Grid, cards, and CTA border-radius all consistently derive from the `--radius` token (`rounded-xl` / `rounded-lg`), so there's no radius drift on this page.
- Eyebrow label, badges, and "Read more" icon correctly use `--primary` for the non-interactive, decorative role the new design system defines for it (aside from the "Read more" ambiguity noted above).
