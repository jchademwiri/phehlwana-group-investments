# UI/UX Audit — Home (`/`)

## Summary
The homepage is well-structured and largely fixed the accessibility bugs flagged in the prior audit (hero `alt` text is now bound correctly, the multi-`<h1>` issue is resolved, the redundant PNG preload is gone). The remaining problems are mostly about consistency: the new `--primary` / `--interactive` split isn't applied uniformly (a few real links still use `text-primary`, one purely decorative badge uses `bg-interactive`), there's no dedicated focus-visible treatment anywhere on the page, and two card grids wrap their click target in `overflow-hidden`, which risks clipping the keyboard focus ring entirely. Typography scale and section radius also drift slightly across sections that should read as siblings.

## Findings

## What's Working Well
- The two high-severity issues from the previous audit are fixed: hero `Picture` now correctly passes `alt={slide.alt}` (`index.astro:108`), and only the first carousel slide renders an `<h1>` while the rest render `<h2>` (`index.astro:125-133`) — there's a single `<h1>` in the DOM.
- The redundant PNG hero preload flagged before is gone; `Layout.astro` now preloads only the responsive WebP `imagesrcset` set (`Layout.astro:100-108`).
- The hero carousel correctly pauses auto-rotation on `mouseenter`/`focusin` and resumes on `mouseleave`/`focusout`, and respects `prefers-reduced-motion` — a real WCAG 2.2.2 fix (`index.astro:443-453`).
- Decorative use of `--primary` is mostly correct and consistent: eyebrow labels (`index.astro:122, 188, 259, 356`), icon-dot backgrounds for values/trust items (`index.astro:211, 324`), and icon strokes throughout all read as "structural," not clickable — exactly the intended role.
- `Header.astro` itself is a strong reference implementation of the primary/interactive split: active nav/dropdown states use `bg-interactive`/`text-interactive`, decorative icons use `text-primary`, and it correctly reserves `--interactive` for anything actually clickable.
- `Picture.astro` handles responsive `srcset`/`sizes` and WebP-with-fallback cleanly, and `loading='eager'` is scoped to only the first hero slide, with everything else lazy — good LCP hygiene.
- Section vertical rhythm mostly follows a consistent `py-16 lg:py-24` pattern across About/Services/Featured Projects, giving the page a coherent scroll cadence outside the few call-outs above.
- The "no featured projects" case is handled gracefully — the whole section is conditionally omitted (`index.astro:352`) rather than rendering an empty grid.
