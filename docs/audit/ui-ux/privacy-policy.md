# UI/UX Audit — Privacy Policy (`/privacy-policy`)

## Summary
Content and legal structure are solid (unchanged from the prior audit's positive read), but the page has one real cross-linking gap and a systemic typography issue shared with its new sibling page: prose line length is wider than recommended, and the shared `.prose` link color token doesn't follow the new primary/interactive split. Structurally the page is a good template — Terms of Service now mirrors it closely, which is discussed in that page's own report.

## Findings
| Severity | Area | Finding | Recommendation | Location |
|---|---|---|---|---|
| Medium | Cross-linking | Terms of Service links back to Privacy Policy (`src/pages/terms-of-service.astro:96-98`), but Privacy Policy has no reciprocal link to Terms of Service anywhere in its content. A visitor reading the privacy policy has no way to discover the ToS exists except via the footer. | Add a matching "See also our Terms of Service" line at the end of the page, mirroring the pattern already used in `terms-of-service.astro`. | `src/pages/privacy-policy.astro:93-103` (no equivalent block present) |
| Medium | Reading experience | `.prose` is given `max-w-4xl` (896px) directly, overriding Tailwind Typography's default `65ch` measure. At the default 16px prose body size this produces a line length well beyond the ~75-character readability guideline, especially on wide desktop viewports where the outer `container` (1280px) doesn't further constrain it below 896px. | Reduce to `max-w-2xl`/`max-w-3xl` (or add `prose-lg:max-w-prose` equivalent) so line length lands closer to 65-75 characters. | `src/pages/privacy-policy.astro:27` |
| Low | Design system consistency | `.prose` link color (`--tw-prose-links` / `--tw-prose-invert-links`) is bound to `var(--color-primary)`, the decorative/structural token, not `--interactive`, the token the design system reserves for clickable elements. It isn't visibly wrong on this page today only because the one real link (`mailto:` in the contact box) has an explicit `text-interactive` override — but any future inline link added to the body copy without a manual override will render in the wrong (non-interactive) color and won't match the site's link-affordance convention. | Change `--tw-prose-links` / `--tw-prose-invert-links` to `var(--color-interactive)` in the shared stylesheet. | `src/styles/starwind.css:208`, `src/styles/starwind.css:226` |
| Low | Navigation / TOC | Nine `<h2>` sections are numbered in the copy ("1. About...", "2. What Personal..." etc.) but none carry an `id`, so there's no way to deep-link to a specific section and no anchor-based table of contents is offered despite the numbering implying one. | Add `id` attributes to each `<h2>` (e.g. slugified from the heading text) and consider a simple sticky-scroll TOC sidebar at `lg:` breakpoints, matching the numbered structure already implied by the copy. | `src/pages/privacy-policy.astro:34-93` (no `id=` attributes present on any heading) |
| Low | Content freshness (carried over) | Prior audit's note about Vercel/Resend being named as data processors (Section 6) is still applicable if those providers change. Not a UI issue but still open. | Update copy if processors change. | `src/pages/privacy-policy.astro:72-75` |

## What's Working Well
- Clear page header pattern ("Legal & Compliance" eyebrow in `--primary`, bold `h1`, muted intro paragraph) that reads as a coherent, intentional template — and Terms of Service now reuses this exact pattern, giving the pair strong visual consistency.
- Numbered heading structure (1-9) makes the document easy to scan even without a TOC.
- The `.prose` customizations in `src/styles/starwind.css:242-289` (tightened `h2`/`h3` spacing, bottom-border under `h2`, styled tables/blockquotes/inline code) all correctly reference design tokens (`var(--color-border)`, `var(--color-primary)`, `var(--color-accent)`) rather than hardcoded colors, so the page adapts cleanly to dark mode.
- The closing contact block (`src/pages/privacy-policy.astro:97-103`) is pulled out of `.prose` flow via `not-prose` and uses `bg-muted`/`border-border`, correctly landing on the Apple-style elevation tiers in dark mode instead of inheriting prose's plain background.
- Responsive: header section scales padding at `lg:` (`pt-36 pb-14 lg:pt-44 lg:pb-20`), and the content section relies on `container` + `mx-auto` for consistent gutters at all widths — no fixed-width elements that would overflow on mobile.
- Legal content itself is genuinely POPIA-specific (not generic boilerplate) — the review notes at the bottom (Information Officer contact, rights under POPIA, consent basis) show real product/legal care.
