# UI/UX Audit — Shared Service Layout (`src/layouts/ServiceLayout.astro`)

## Summary
`ServiceLayout.astro` is the shell for all 5 detail pages (construction, mechanical, cleaning, plant-hire, security) and is generally solid: correct breadcrumb/schema markup, a reasonable hero treatment, and consistent color-token usage (`text-primary` for structural/eyebrow elements only). The main issues are a hero gradient/text-legibility risk over photographic backgrounds, an oversized min-height hero for what is often thin subtitle copy, and a safety section that is identical, word-for-word, across all 5 pages with no service-specific customization — which is a missed opportunity rather than a bug. These issues affect every detail page identically, so they're documented once here.

## Findings
| Severity | Area | Finding | Recommendation | Location |
|---|---|---|---|---|
| High | Hero legibility | The hero image sits behind a gradient (`from-background/95 via-background/60 to-background/30`, bottom-to-top) and the h1/label/subtitle are placed in the *bottom* portion of the hero (`items-end`, content in `pb-10 pt-36`) where the gradient is strongest (95% background opacity) — good. But the breadcrumb sits just above that, in the `mb-5` block, which is still within the 95%-opacity zone, so it should be legible; however for pages with lighter/brighter source photography (not verified per-image), contrast should be spot-checked, since the gradient's opacity, not a fixed scrim, is the only legibility guard (unlike the site header, which uses a hardcoded `rgb(0 0 0 / 0.55)` scrim per `starwind.css:310-317`). | Verify contrast across all 5 hero images (light sky vs dark machinery), or add a flat scrim similar to the header's `::after` treatment for guaranteed legibility regardless of source image brightness. | `src/layouts/ServiceLayout.astro:73-77` |
| Medium | Hero sizing | `min-h-[320px] lg:min-h-[380px]` is a fixed pixel min-height unrelated to actual content length — on pages with short subtitles (e.g. Mechanical's is a single line) vs. long ones (Construction's wraps to 2 lines), the hero height is visually inconsistent relative to content, and on mobile with a long title + breadcrumb + subtitle stacked in `pt-36`, content may push close to or past `min-h-[320px]`, meaning the min-height stops doing useful work. | Consider `min-h-fit` bounded by a `max-h` instead, or verify against real device testing that no page's content overflows the hero at narrow viewports. | `src/layouts/ServiceLayout.astro:59` |
| Medium | Repeated content | The "Safety is Non-Negotiable" section (heading, body copy, and the 6-item checklist) is byte-for-byte identical across all 5 service pages — including for Cleaning and Plant Hire, where the checklist item "Formal risk assessments before high-risk activities" reads oddly generic. | Consider service-specific variants (e.g. mention PSIRA for security, NEM:WA for cleaning/waste) via a prop, or accept the duplication as an intentional trust-signal repeated site-wide (currently reads as boilerplate copy-paste). | `src/layouts/ServiceLayout.astro:148-198` |
| Low | CTA copy duplication | Both the safety section's parent page and the final `ContactCTA` reuse near-identical "quote" messaging ("free, no-obligation quote... responds within 1 business day") that also appears verbatim on the services overview page's own `ContactCTA` (`src/pages/services/index.astro:177-178`). Not wrong, but there's no differentiation between the overview CTA and each detail-page CTA beyond the `service=` query param. | Consider a per-service CTA body line reflecting a first-step relevant to that trade, though this is a minor content nicety, not a UX defect. | `src/layouts/ServiceLayout.astro:200-205` |
| Low | Breadcrumb duplication | Breadcrumb markup (SVG chevrons, list structure) is hand-duplicated here rather than reusing the shared `PageHeader.astro` component's breadcrumb rendering, which already exists and handles an arbitrary list of crumbs (`src/components/sections/PageHeader.astro:32-76`). Both implementations are visually similar but this is duplicate code with two places to keep in sync if breadcrumb styling changes. | Extract breadcrumb rendering into a shared partial/component used by both `PageHeader.astro` and `ServiceLayout.astro`. | `src/layouts/ServiceLayout.astro:82-123` |
| Low | Color usage | Eyebrow labels ("Construction & Civil Engineering", "Health & Safety") correctly use `text-primary`, and the safety checklist's checkmark icons use `text-primary` (decorative, non-interactive) — both correct per the new primary/interactive split. No interactive elements in this layout misuse `primary` in place of `interactive`. | None — flagging as confirmed-correct for the record. | `src/layouts/ServiceLayout.astro:125-129, 152-156, 180` |

## What's Working Well
- Correct, consistent use of `text-primary` for all non-interactive/decorative elements (eyebrow labels, checkmark icons, dots) across the entire shared layout — no accidental `interactive` bleed into decorative contexts.
- `ContactCTA` (used at the bottom of every detail page) correctly uses `bg-interactive` for the actual clickable button — the split between decorative `primary` and interactive `interactive` is respected end-to-end.
- Solid SEO/structured-data implementation: both `Service` and `BreadcrumbList` JSON-LD schemas are generated per-page from props, with correctly resolved absolute URLs via `Astro.site`/`Astro.url`.
- `serviceParam` is threaded through to the CTA's `btnHref` as a query param (`/contact?service=...`), pre-filling context for the contact form — a genuinely useful cross-page UX touch.
- Picture component usage in the hero includes responsive `widths`/`sizes` for the large hero image, with `loading='eager'` appropriately applied since it's above-the-fold content.
- Consistent `data-animate` scroll-in treatment applied to the safety section, matching the rest of the site's motion language.
