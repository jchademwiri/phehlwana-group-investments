# UI/UX Audit — Thank You (`/thank-you`)

## Summary
A short, purpose-built confirmation page that does the basics right: clear success message, an SLA promise, and two well-differentiated CTAs (primary "Back to Home" vs. secondary "View Our Services"). It's a small surface area so findings are minor, but there's a real color-semantics gap (the success icon uses `--primary` rather than the site's own `--success` token) and a layout sizing issue that can force unnecessary scrolling on short mobile viewports.

## Findings
| Severity | Area | Finding | Recommendation | Location |
|---|---|---|---|---|
| Medium | Color usage | The success checkmark icon uses `bg-primary/10 text-primary` — the decorative/structural token — even though this is the one place on the site whose entire purpose is to signal "success." The design system already defines `--success`/`--success-foreground` and uses it correctly for confirmed items on `about.astro:386` (`bg-success/20`, `text-success-foreground`). Using two different colors for the same "confirmed/success" meaning across pages is an inconsistency the new token split was meant to prevent. | Change the icon container to `bg-success/20 text-success-foreground` (or equivalent) to match the semantic token used elsewhere for confirmation states. | `src/pages/thank-you.astro:13-15` |
| Medium | Responsive layout | The section combines `min-h-[70vh]` with `pt-40 pb-20` (`pt-40` = 10rem/160px on top of the 70vh minimum). On short mobile viewports (e.g. landscape phones, or portrait phones with a visible browser chrome, roughly 500-600px tall), `70vh` + `10rem` top padding + `5rem` bottom padding can exceed the viewport height, forcing a scroll to reach the CTAs on a page whose entire job is "confirm success and offer one tap forward." | Reduce top padding on small screens (e.g. `pt-28 lg:pt-40`) or drop `min-h-[70vh]` in favor of a fixed, content-driven height so the CTAs are reliably above the fold on mobile. | `src/pages/thank-you.astro:10-12` |
| Low | Interactive states | Neither CTA link declares an explicit `focus-visible` style (relying only on the global `* { outline-outline/50 }` base rule), matching the same gap found on `about.astro`'s "View Our Services" link but inconsistent with `contact.astro:367`'s submit button, which explicitly sets `focus-visible:outline-2 focus-visible:outline-interactive`. | Add explicit `focus-visible:outline-2 focus-visible:outline-interactive` to both links for a visibly consistent keyboard-focus treatment site-wide. | `src/pages/thank-you.astro:26-35` |
| Low | UX / dead-end flow | The page is reachable by direct URL/bookmark (it's a plain static route, not gated behind the form-submission redirect at the server level from a visitor's perspective), so a user who bookmarks or is sent this link independently sees a false "Message Received!" confirmation with no way to tell it's stale. | If not already handled elsewhere, consider a lightweight referrer/session check, or at minimum make sure this is an accepted tradeoff rather than an oversight — low severity since the content itself doesn't promise anything false ("thank you for reaching out"), but worth a conscious decision. | `src/pages/thank-you.astro:1-4` |
| Low | Content | The secondary CTA "View Our Services" sends users away from the confirmation without also surfacing a fallback contact channel (phone/WhatsApp) for anyone whose enquiry was urgent — `contact.astro`'s sidebar prominently features a WhatsApp CTA and phone numbers that don't carry over here at all. | Consider a small "Need it urgently? Call 012 655 0284 or WhatsApp us" line beneath the two buttons, mirroring the urgency messaging established on the Contact page's FAQ. | `src/pages/thank-you.astro:25-36` |

## What's Working Well
- Clear, minimal single-purpose layout with no competing content — appropriate restraint for a confirmation page.
- Two-tier CTA hierarchy is correctly expressed visually: `bg-interactive` filled button for the primary action ("Back to Home") vs. a bordered/outlined `border-border` button for the secondary action ("View Our Services") — good use of visual weight to match action priority.
- The confirmation icon's wrapping `<div>` is correctly marked `aria-hidden="true"` since the adjacent `<h1>` already conveys the same information in text — no redundant screen-reader announcement.
- SLA messaging ("within 1 business day") is bolded and consistent with the same promise made on `contact.astro:91` and `about.astro:533`, giving the user a coherent expectation across the whole enquiry flow.
- `prerender = true` keeps this static and fast, appropriate for a page with no per-request personalization.
- Uses the same button radius/padding/typography scale (`px-6 py-3 rounded-lg text-sm font-semibold`) as CTAs elsewhere on the site (e.g. `ContactCTA.astro:37`), keeping the button language consistent even where the shared component isn't reused directly.
